## Behavior and boundaries

Signed clients has compact intersecting status/owner/follow filters and
company/status/owner sorting in both directions, blank-last and deterministic
ties. These apply to the **loaded page only**, explicitly labelled. Existing
Name search and API paging stay server-side. No extra calls come from local
filters. Account changes clear account-specific filter state.

Sourcer Search can create/select a folder before paid consent. The tab remembers
its selection on reload, refreshes folders when returning from Candidates, and
pins the destination to a run. The service validates the destination before
provider work. Existing same-run organisation is preserved; deleting a target
mid-run produces a visible archive warning with paid results/usage retained,
without implicit recreation or replay. All candidate organisation still uses
the protected vault's existing version2 format; no SQLite/schema migration.

The normal query normalizer keeps one core term from every positive AND group,
then allocates remaining optional alternatives up to four terms/three operators.
Quoted words remain literal. Overbudget NOT/mixed nesting/more than four required
groups fail visibly. Recruiter/Lite/review-open-search are unchanged. No extra
provider request, retry or automatic paid consent is added.

Country acceptance requires the requested visible label, singleton observed
numeric geo filter, same keyword and all other filters, and stable metadata
before/after the read. A pending matching location navigation waits; changed
filters fail. Ambiguous interrupted steps remain non-replayable across worker
restart. Fresh normal searches require `people_country_ready_revision: 1` before
planning. **Update the app and companion together.**

124 route URLs, existing guards, structured errors, credentials, provider/paid
boundaries and owner-data authority remain. Source identity was generated by
`bump_version.py`; `cvstudio_linkedin_sourcer.py` retains CRLF.
