Pinned navigation stacking-context fix (v24.6.153):
- Root cause: `.app` contains the navigation, while several later feature views (including OneNote and Dashboard) are body-level siblings. Wallpaper mode gives every direct body child `position: relative; z-index: 1`, creating sibling stacking contexts. A fixed navigation left inside `.app` cannot out-rank later sibling views, so those views can paint over it and make the navigation appear to slide away.
- While floating, the navigation is now temporarily portalled to `document.body` and assigned a high application-layer z-index below the Owl/settings modal layers.
- The original spacer remains inside `.app`, preserving exact width, left alignment, and page height. Unpinning or returning above the anchor restores the navigation immediately after the spacer.
- Pin preference, toggle placement, 760px mobile cutoff, persistent red OneNote picker attention, tab order/locks, and all backend behaviour remain unchanged.

## v24.6.207 AI Crawler preview reuse, serial shortlist prefetch and two-phase status

- Candidate previews now use three deliberately bounded layers: a frontend payload LRU, a detached rendered-DOM LRU for instant recent revisits, and an account-scoped backend JSON LRU validated by the latest JobAdder attachment fingerprint.
- Reopening a recently viewed candidate reattaches the already-rendered preview without another network request or loading flash.
- All currently displayed shortlisted candidate previews are queued for strictly serial background prefetch. Foreground card clicks pause or promote the queue, always take priority, and reprioritize neighbouring cards before the remaining shortlist.
- Ordinary background failures are silent. A 401/403 stops the remaining queue after the first rejection and shows one reconnect/lock warning, preventing a preview-request storm. A new search, Clear, unlock reset or stale-run invalidation cancels the queue and clears frontend CV data.

No sensitive preview payload is persisted to browser disk storage. Background prefetch eagerly decodes only the first two visual pages so it does not make the active preview sluggish.
- The backend still performs the cheap latest-attachment listing on every preview request. Attachment ID/type/name/timestamps/size form the validator, so replacing a JobAdder resume causes a fingerprint miss and fresh rendering. Legacy tenants that return no attachment metadata deliberately bypass the backend LRU rather than risk serving a stale CV from an unvalidated empty fingerprint.
- AI Crawler now keeps one orange in-app tab outline across both phases.
