# Public job-link autofill corrective — 2026-10-19

Historical release evidence; root `VERSION` is the live release identity.

## Reproduced problem and correction

Owner reported blank fields and requested direct inspection. The actual in-app
Job Leads form contained a valid public job URL and the companion timeout
message. The previous implementation required a Chrome extension that cannot
run in the in-app browser. Earlier simulated-companion tests did not establish
that the owner's real workflow worked.

Source v24.6.449 on `codex/v24.6.449-job-link-public-read`, from unmerged v448
`94fbe8c`, adds a public HTML reader behind POST `/job-leads` action `lookup`.
Default paste now works directly in the app. The existing companion remains an
explicit fallback for ads requiring sign-in. No login or access check is bypassed.

The app-independent public reader accepts only canonical supported LinkedIn job
URLs, follows at most three same-job redirects, strips tracking/query values,
bounds HTML to 4 MiB and limits concurrent reads. Fresh requests carry no user
cookies or authentication; an explicit callback prevents .netrc credential use.
Structured JobPosting IDs/canonical URLs confirm the requested ad. Recommended
jobs and unrelated search headers are excluded. A canonical public top card is
the narrow markup fallback. Responses are plain fields, never executable HTML.
Only empty job fields fill; contacts/notes/status/dates retain the v448 behavior.

No route is added: exact 120-route seal, five ordered guards, main schema 10,
Job Leads schema 1, journal and all paid/provider/Sourcer contracts remain.
The new module is in architecture/build/compilation inventories and version
surfaces were generated by bump_version.
